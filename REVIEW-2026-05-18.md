The visual identity remains the strongest move on the page — cream (`#e8e5d8` / `#d8d3c0`) + terracotta (`#8b5a2a`) + an Anton / Cormorant Garamond / JetBrains Mono trio still read as "bound printed journal" and nothing else looks like it. The `~ shipped today` and `● LIVE` labels are charming when true and embarrassing when not; one needs to drive the other. And the WCAG contrast fail, the hard-coded 8.5rem hero, the missing `:focus-visible`, the four-family font payload, and the old Jekyll site at `ask149.github.io` all remain open from v1 because the 5th reviewer did not verify them.

Fix the H1 semantics, add GitHub + Twitter, add a one-line `Previously` strip, decide what the chip-row promises — that is a 90-minute sprint. Everything else is grace notes.

## Item-by-item specifications (new and changed items only)

For v1-carryover items (Blockers 2-3, Open O1-O7, Minor M1), the original specifications stand — full detail in the git history of this file or in the open-question discussion that produced them.

### 🔴 1. H1 semantics — split into proper heading + paragraphs (NEW)

**Current:** One `<h1>` element wraps four `<generic>` blocks (name, role, tagline, and likely a status line). Visually fine; semantically a run-on for screen readers and a single-blob signal for search.

**Fix:** Restructure markup so each piece is its own element. Visual stack stays identical via CSS; the DOM stops lying to assistive tech and crawlers.

```html
<h1>Ashish Kshirsagar</h1>
<p class="role">Software Engineer at Microsoft</p>
<p class="tagline">Ships to Windows · Builds with agents</p>
```

**Why blocker:** Screen-reader users currently hear one announcement; SEO sees one undifferentiated string. Both fixes ship together with item 4 (tagline copy) for one focused commit.

**Location:** `src/components/coder/WorkshopHero.astro`.

- `Agentic AI enthusiast` → **`Builds with agents`** or **`Runs a four-agent studio`** — the rest of the page demonstrates *practice*, not enthusiasm. Match the verb to the evidence.

## Bringing the receipts back — a strategic question

The old `ask149.github.io` carries real receipts: **Tesla intern, Amazon, Barclays (2y), Google intern, ASU MS CS, CERN-HSF, GSoC 2021.** The rebuild currently surfaces none of them. For a cold recruiter visit, the new site asks the reader to trust the "senior engineer at Microsoft" line without any of the prior-decade proof points that justify "senior."

**Recommendation: B + A together. Highest yield, lowest tone risk.**

### Option B — One-line "Previously" strip in the hero (do this first)

Under the contact row, a single line:

> *Previously: Microsoft · Tesla · Amazon · Barclays · Google (intern) · CERN-HSF*

Six names. No prose. Costs ~24px of vertical space. Buys enormous credibility for cold visitors who have ten seconds and one screen.

**Lowest effort, highest yield.** Ship this with the 90-minute sprint.

### Option A — `/resume` page as a story, not a PDF link (do this second)

A new `/resume` route. Vertical timeline: role · company · year · one-line outcome per role. Same names as the old `ask149.github.io`, rewritten in the new editorial voice. The home page stays uncluttered; the receipts are one click away and indexed for search.

Not a PDF download. A page. The PDF can live as a `↓ download` link on that page for recruiters who insist.

### Option C — `/cv` section under the §-system (skip unless already adding a section)

`§5 · the ledger`. Only adopt if a 5th section is being added anyway — do not invent slots to hold the receipts.

### Explicit DO-NOT

**Do not paste the old `ask149.github.io` "About me" prose verbatim** ("painted with the Google colors," "wielded my coding prowess") into a card on the home page. It solves the credibility problem and creates a tone problem of equal size. The new editorial voice and the old grad-student voice cannot share a page.
